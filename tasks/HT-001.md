## Problem

CON-001 이 승인됐지만(90/100) 코드가 0 이다. `nan/gates.yaml` 의 M1 은
**"첫 3분이 실제로 플레이된다"** 이고, 이 프로젝트에서 그것이 세로 조각의 정의다.

이 조각이 답해야 하는 질문은 하나다 —
**강화하고 배당을 보고 거는 것이 재미있는가.**

컨셉이 스스로 지목한 최대 위험은 밸런스가 아니라 **두 게임이 안 물리는 것**이었다.
그것을 "강화 결과는 나만 안다"로 풀었는데, **그 연결이 실제로 손에 잡히는지는
플레이해야 안다.** 안 잡히면 이 게임은 슬롯 두 개다.

## What we are shipping

경주 **2회**가 처음부터 끝까지 도는 한 판. 시작 → 이름 짓기 → (강화 → 배당 → 베팅
→ 경주 → 정산) × 2 → 결산.

### `stable` — 내 말과 강화

- 능력치 셋: **속력 · 가속 · 체력.** 각각 단계 1~10, 시작은 전부 **3**.
- 강화는 **능력치 하나를 골라** 시도한다. 비용은 단계에 비례.
- **결과 3갈래** — 성공(+1) / 실패·보존(변화 없음) / 실패·감소(−1, 하한 1).
  확률은 CON-001 표 그대로 9행. **세 숫자를 화면에 전부 적는다.**
- 말 **이름을 짓는다.** 기본값은 절차 생성(형용사 + 명사), 사용자가 고칠 수 있다.

### `race` — 경주 · 배당 · 정산

- 출주 **6두**(내 말 1 + 상대 5). 상대 능력치는 시드로 생성하고 경주마다 조금씩 세진다.
- 거리는 **1000~2000m** 중 하나. 거리에 따라 스탯 가중치가 다르다.

  | 거리 | 가속 | 속력 | 체력 |
  |---|---|---|---|
  | 단거리 1000~1200 | **높음** | 중간 | 낮음 |
  | 중거리 1400~1600 | 중간 | **높음** | 중간 |
  | 장거리 1800~2000 | 낮음 | 중간 | **높음** |

- 경주는 **구간 시뮬**이다. 트랙 기하 없이 구간마다 속도를 계산해 누적 거리로 착순을 낸다.
  체력이 모자라면 후반 구간 속도가 떨어진다 — **"마지막 직선에서 잡힌다"가 여기서 나온다.**
- **패리뮤추얼 배당.** 가상 관중이 각 말에 판돈을 건다(강함의 추정치에 비례 + 잡음).
  **내 베팅도 같은 풀에 들어간다.**

      배당 = (승식 총 판돈 × (1 − 공제율)) ÷ 적중 판돈

  공제율 **20%**, 화면에 표기한다.
- **승식 2종만** — `연승`(지정 말이 3착 이내) · `단승`(1착).
  CON-001 이 첫 조각을 2종으로 못 박았다. **여기서 늘리지 않는다.**

### 화면

- 캔버스 **960×640.** DESIGN.md 가 미정으로 뒀던 값을 여기서 정한다 —
  640×480 은 nan 의 전제이고, 이 게임은 배당표·확률 3종·스탯 3종을 동시에 띄운다.
- 페이즈 넷: **마방 → 창구 → 트랙 → 정산.** 각 화면은 한 가지만 묻는다.
- **치비 말 렌더** — 2.5등신, 굵은 외곽선, 납작한 채색, 표정 3종(기본·기쁨·슬픔).
- **강화 판정 3단 연출** — 돌린다(0.8s) → 감속(0.55s) → 판정(0.3s).
  **결과를 먼저 확정하고 화면만 늦춘다**(nan PSH-004 에서 통한 구조).
- **숫자는 UI 층, 캐릭터는 트랙 층.** 귀여움이 판단 재료를 가리지 않는다.

### 검증

- 강화 확률표가 **행마다 합 100** 이고, **감소 확률이 단계에 따라 단조 증가**한다.
- 패리뮤추얼 항등식: **적중자 총 지급액 = 총 판돈 × (1 − 공제율)** (반올림 오차 이내).
- **내가 크게 걸수록 내 배당이 내려간다** — 실제 경마의 성질이자 몰빵 제동.
- 거리별 스탯 가중치가 실제로 착순을 바꾼다(같은 말이 단거리/장거리에서 다르게 들어온다).
- 결정성: 같은 시드 = 같은 경주.

## What we are not shipping

- **승식 5종**(복승·복연승·쌍승·삼복승·삼쌍승). M1 은 2종이다.
- 경주 8~12회 전체 진행. **M1 은 2회다.** 전체 완주는 M2.
- 국면 곡선 튜닝 · 실측 길이. M3.
- 저장·이어하기. 한 자리에서 끝나는 게임이라 필요 없다.
- 사운드 · 파티클 · 화면 전환 연출(강화 3단 연출은 예외 — 이게 punchline 이다).
- 관중 판돈 모델의 정교화. M1 은 "강함 추정 + 잡음" 한 줄이다.
- 스탯 4번째(근성 등) · 장비 · 기수 · 컨디션.

## Facts

- 코드가 0 이다. `src/main.ts` 는 "컨셉 승인 대기" 한 줄짜리 자리표다.
- `DESIGN.md` 가 화면 규격을 **의도적으로 미정**으로 뒀다. 이 작업이 정한다.
- nan 의 `kits/layout`·`ui/tokens`·`core/harness` 를 **아직 옮기지 않았다.**
  M1 에 필요한 만큼만 새로 쓴다 — 안 쓰는 하네스를 미리 옮기지 않는다.
- 확률표 27개 값은 CON-001 에 있고 **전부 근거 없이 고른 값**이다.
- 패리뮤추얼에서 **적중 판돈이 0 이면** 배당이 정의되지 않는다.
  실제 경마는 환급(특별 배당)한다 — 이 경우를 반드시 처리한다.
- 출주 6두면 연승 3착 이내는 **절반**이다. 배당이 낮아 안전망 역할에 맞는다.

## Decisions

- **캔버스 960×640.** 배당표(6행) + 확률 3종 + 스탯 3종이 한 화면에 들어가야 한다.
- **엔진과 렌더를 가른다.** `systems/` 는 캔버스를 모른다 — nan 에서 통한 구조이고
  시뮬레이션 테스트가 가능해진다.
- **구간 시뮬**로 간다. 트랙 기하(코너·주로)는 M1 에 없다 —
  체력이 후반에 듣는 것만 있으면 대표 장면이 성립한다.
- **관중 판돈은 "겉으로 보이는 강함"에서 나온다.** 내 말의 강화 결과는 **안 들어간다** —
  이것이 컨셉의 핵심이고, 여기서 배당과 진실이 갈린다.
- **적중자 0 이면 전액 환급.** 배당을 무한대로 두지 않는다.
- 강화 비용은 **단계 × 100 G**. 근거 없다 — M2 에서 조정한다.

## Assumptions

- 시작 골드 **1,000 G** 가 "2경주에 강화 1회 + 베팅 2회"에 맞는 값이라고 가정했다.
- 상대 5두의 초기 능력치 평균이 내 말(전부 3)과 비슷해야 첫 경주가 승부가 된다고 가정했다.
- 거리별 가중치 3종이 착순을 실제로 바꿀 만큼 차이가 난다고 가정했다 —
  **차이가 작으면 "다음 경주 보고 스탯 고르기"가 죽는다.** 검사로 확인한다.
- 6두 치비 말이 화면에서 구분된다고 가정했다. **사람이 봐야 안다.**
